Dual-track design

Two research questions, clearly separated

Combining an original small model with a fine-tuned pretrained model would obscure both results. XRFM keeps the lineages distinct in code, documentation and model metadata.

Track A · Native

Original decoder-only transformer

25M and 85M parameter checkpoints trained from random initialization on a 20.08M-token multilingual and code corpus. Grouped-query attention, RoPE, RMSNorm and SwiGLU are implemented directly in PyTorch.

  • T4 32K Script-Protected Byte-BPE tokenizer
  • Exact checkpoint resume probe with zero weight difference
  • Per-language held-out BPB measurements

Track B · CoderSec

Attributed QLoRA security track

A specialized coding and defensive-security line based on Qwen3-1.7B, with NF4 QLoRA fine-tuning and a curated SFT corpus. The base model and its Apache-2.0 license are explicitly attributed.

  • Base revision `70d244cc`
  • SFT dataset revision `808d7505`, 24,100 rows
  • Checkpoint publication: not yet available

Evidence, not marketing

What the published checkpoints actually show

BPB measures how many bits a model needs per byte of held-out text. It is a compression and likelihood metric. A lower BPB does not establish coding skill, factual accuracy or cybersecurity capability.
